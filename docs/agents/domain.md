# 领域文档

本文件说明工程技能在探索代码库时如何使用领域文档。

## 探索前需要读取

- 如果存在，读取根目录的 `CONTEXT.md`
- 如果存在，读取根目录的 `CONTEXT-MAP.md`
- 如果存在，读取 `docs/adr/` 中与当前工作区域相关的 ADR
- 多上下文仓库还需要检查 `src/<context>/docs/adr/` 中的上下文级决策

如果这些文件不存在，应静默继续，不要专门报告缺失，也不要提前建议创建它们。`/domain-modeling` 技能会在确实需要解决术语或决策时按需创建。

## 文件结构

当前仓库采用 single-context 布局：

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
└── src/
```

## 使用术语表中的词汇

在问题标题、重构提案、假设或测试名称中描述领域概念时，应使用 `CONTEXT.md` 中定义的术语。不要随意使用被术语表明确避免的同义词。

如果所需概念尚未出现在术语表中，这通常意味着：

- 项目正在引入项目尚未使用的新术语；或
- 领域文档存在需要通过 `/domain-modeling` 解决的缺口。

## 标记 ADR 冲突

如果输出与现有 ADR 冲突，应明确指出，而不是静默覆盖。例如：

> 与 ADR-0007 冲突（事件溯源订单），但由于……，值得重新讨论。
