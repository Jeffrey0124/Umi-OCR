# 服务商名称联动、模型能力证据与展开操作

Status: ready-for-human

## 行为

- 点击服务商按钮，将配置名称设为其显示名称；再次点击当前服务商也可恢复名称，保留当前接口与密钥。名称始终允许手动编辑，打开已保存配置保留自定义名称。
- 模型列表读取接口明确提供的图片输入声明，如 `architecture.input_modalities`、`input_modalities`、严格布尔值 `supports_vision` 或 `capabilities.vision`。不根据模型名称、图片输出模态、描述文案或 Gemini 的生成方法猜测图片输入能力。
- 显示“支持图片（服务商声明）”“OCR 测试通过”“能力未知／未测试”；已失败的测试显示“测试未通过”。声明和通过标记可以同时存在，不删除任何模型。
- 实际 OCR 测试须在返回文本中找到内置图片的 `UMI OCR TEST 123`，忽略大小写、空白和标点。仅接口可连接或返回无关内容不产生通过标记。
- `modelEvidence` 随配置持久保存，按模型区分，使用服务商、地址和密钥池的摘要限定范围；更换这些字段后失效。草稿取消、旧请求、关闭弹窗和已修改的保存配置均不能污染其他配置或模型。
- 配置卡片直接展示测试连接、编辑、复制、启停、删除；启用的非默认项显示设为默认，当前默认只显示一处标签。窄窗口操作自动换行。
- 本轮软件和安装版本同步为 2.1.7。

## 验证

- 65 项 Python / Qt 测试通过，含元数据去重、不猜测能力、匹配测试文字、证据失效、名称联动、自定义名称保存、标记持久化重载、旧响应和真实本地 HTTP 识别。
- Qt 5.15 深色、浅色、紧凑窗口检查；预览在 `../previews-v2.1.7/`。模型标签使用独立说明行，长名称省略，列表可滚动。
- 团队安装配置过滤、安装版本一致性及 `git diff --check` 通过；测试未修改用户的 `.settings`。
- 未向真实远程服务商发送请求。未提供能力元数据的服务商显示未知，用户可主动进行实际 OCR 测试。
